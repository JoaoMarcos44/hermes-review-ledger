# Review Ledger procedure 3

1. Resolve the authorized repository, review, and exact HEAD/base snapshot.
2. Recover recorded state, ownership, limitations, and revalidation needs.
3. Select eligible exact versions of guidance. Check conditions and exclusions;
   unknown applicability remains unknown. A lesson is a question, never proof.
4. Investigate concrete questions with authorized host tools. Seek supporting
   and contradictory observations. The Ledger executes no repository code.
5. Record observations, scope, environment, limitations, and missing checks.
   A model report is not independently captured execution. Missing data is not
   a clean review. A useful refutation is valid; zero supported findings is valid.
6. Assess claims against evidence from the exact snapshot. Historical results
   are planning context, not current verification, even when a file is unchanged.
7. Record use and outcome for the exact guidance version actually considered.
   Missing execution is not refutation; unselected guidance has no outcome.
8. Before completing the owned run, proactively assess the current run for a
   reusable conditional lesson; do not wait for the user to ask. If a useful
   lesson is supported, propose it through the existing `ledger_lesson` workflow
   using exact, valid, current-run supporting observations, concrete conditions,
   exclusions, and verification. At least one source must be a complete current-run
   behavioral test report with nonempty details and environment; if these gates
   are not met, do not create a proposal that would await approval. If no lesson
   is justified, make no proposal. This occurs in the current investigation turn,
   with no extra model call or background worker. Explicit automatic mode may
   activate eligible versions through the bounded, audited lesson policy only.
   A model cannot change that policy or invent outcomes to satisfy its gates.
   Automatic activation is not independently verified truth. Optional instructions
   cannot grant permissions or replace this procedure. Protocol changes require a
   deliberate software update.
9. Pause with the current question and missing verification, or complete the
   bounded investigation and export. Saving context never permits skipping
   mandatory verification. A read-only view grants no ownership or approval.
